CORTEX Pattern #001
Source MR: !12 — Add retry handling for authentication API calls
Date: 2026-07-10
Rule: Never swallow authentication errors silently — always log the attempt, the failure reason, and the retry count before retrying
Anti-pattern: Catching AuthError without logging and silently retrying
Language: python
Reason: Silent retries mask systematic authentication failures; without visibility into retry counts the team cannot distinguish transient blips from degraded auth provider health
Established by: @arjun
Status: Active
Examples:
  Bad:  except AuthError:
            retry()

  Good: except AuthError as exc:
            logger.warning("auth retry %d/%d: %s", attempt, MAX_RETRIES, exc)
            retry()

CORTEX Pattern #002
Source MR: !17 — Fix login latency regression
Date: 2026-07-28
Rule: Use the shared retry module (auth.retry.with_policy) for all authentication calls — do not write inline retry loops in business logic
Anti-pattern: Ad-hoc try/except retry loops scattered across service handlers
Language: python
Reason: Inline retry loops diverge over time and cannot be updated centrally; the shared module enforces the org-standard policy (Memory #003) and emits structured retry telemetry automatically
Established by: @sanya, @arjun
Status: Active
Examples:
  Bad:  for attempt in range(3):
            try:
                return auth_client.login(user, pwd)
            except Exception:
                time.sleep(2)

  Good: return auth.retry.with_policy(auth_client.login, user, pwd)
